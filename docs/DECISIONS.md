# Decisions

Defaults chosen while building, with the reason and how to change them. Newest last within each
phase. Format: **decision** — why — how to revisit.

## Phase 1 — skeleton

### Hardware reality check
The build machine is a **Raspberry Pi 4 Model B (4 GB) running Ubuntu 26.04 + GNOME**, not a Pi 5
on Raspberry Pi OS, and the panel is on HDMI (no DSI Touch Display 2 detected). Everything is
written to work on both: the kiosk launcher supports GNOME (XDG autostart) and labwc (Pi OS), the
audio stack uses plain ALSA tools, and the UI's renderer drops quality automatically on the weaker
Pi 4 GPU. Nothing assumes Pi-5-only features.

### Toolchain: uv workspace + pnpm workspace
Python 3.12 (pinned in `.python-version`; uv fetches it if the OS ships something else — Ubuntu 26.04
ships 3.14, for which some audio/ML wheels like onnxruntime lag). One `uv.lock` for all Python
services; one `pnpm-lock.yaml` for all frontends. Toolchains install user-locally (`~/.local`), so
only apt packages need sudo.

### Protocol: pydantic is the source of truth
`packages/protocol/src/jarvis_protocol/events.py` defines every event as a frozen pydantic model in
a discriminated union on `type`. `make protocol` exports JSON Schema and generates TypeScript with
`json-schema-to-typescript`; CI (`make protocol-check`) fails if the generated files drift. Fields
with defaults are marked required in the serialization schema because the server always sends them,
which keeps the TS union narrowable. Extra fields are rejected (`extra="forbid"`).

Events beyond the required minimum: `hello`, `status.update`, `listen.level` (mic level for the
core), `listen.end` (endpointing result), `agent.confirm_request`, `agent.progress`, `tts.sentence`
(subtitles), `playback.done` (node finished playing — the brain uses this, not `tts.end`, to open
the follow-up window), `node.command`, `ui.command`, `ui.snapshot`.

### Audio on the wire: binary frames with a stream id
Binary WebSocket frames are `uint32 LE stream_id + PCM s16le mono`. Mic audio is 16 kHz; TTS audio
uses the sample rate announced in `tts.start`. The node drops frames for any stream other than the
current one, so barge-in can't play stale audio that was already in flight.

### The brain owns the state machine
`IDLE → WAKE → LISTENING → THINKING → (TOOL) → SPEAKING → FOLLOW_UP → IDLE`, any → `ERROR → IDLE`.
It lives in `jarvis_protocol.state_machine` (pure, exhaustively tested) and the brain drives it. Edges
added beyond the spec, each for a real path: `IDLE → LISTENING` (tap-to-talk skips WAKE),
`THINKING → LISTENING` (confirmation questions and barge-in while thinking),
`THINKING → FOLLOW_UP` (empty reply), `FOLLOW_UP → WAKE` (wake word during the window),
`SPEAKING → THINKING/TOOL` (multi-step agent turns that speak between tool calls).

### Network binding
Every listener binds to `127.0.0.1` or a Tailscale address (`100.64.0.0/10`, `fd7a:115c:a1e0::/48`);
the brain refuses to start otherwise (`settings.is_safe_bind`). `0.0.0.0` is accepted only inside a
container, where compose publishes ports on `${TAILSCALE_IP}` only. The kiosk UI server binds to
`127.0.0.1` only.

### WebSocket auth
The audio node and kiosk present a shared device token (`JARVIS_NODE_TOKEN`, generated by
`make env`): `Authorization: Bearer` for the node, `?token=` for the browser (browsers can't set
WebSocket headers). `/ws/ui` also checks `Origin` against `UI_ORIGINS`. An empty token is accepted
only when `JARVIS_ENV=dev`. The token reaches the browser via `/config.json` served by the
localhost-only UI server — it's never baked into the build.

### UI rendering: raw Three.js shaders, no post-processing
The core is an icosphere with simplex-noise vertex displacement, fresnel rim and flowing filaments in
the fragment shader; "bloom" is an additive halo billboard with analytic falloff, not an
`UnrealBloomPass` (a full-screen blur chain is too expensive on the Pi GPU). All passes use ONE/ONE
premultiplied blending with alpha = brightness, so the transparent canvas composites cleanly over
the CSS vignette.

Quality presets (`high`/`medium`/`low`: mesh detail, noise octaves, particle count, frame cap,
pixel ratio). In `auto` mode the renderer measures fps over 3 s windows and only ever steps *down*
(high→medium below 50 fps, medium→low below 40), so it can't oscillate. `low` caps at 30 fps.
Per-frame values (audio levels, easing) bypass React entirely.

Night mode and screen sleep are one black overlay (no CSS filters over the canvas); when asleep the
renderer stops drawing. The panel itself isn't powered off — that needs compositor-specific DPMS
control; revisit if burn-in or power matters.

### Kiosk UI served by a 60-line Python server on the Pi
`deploy/ui-server.py` serves `apps/ui/dist` on `127.0.0.1:8080` with an SPA fallback and a runtime
`/config.json` (brain URL + token from `.env`). No nginx, no Node at runtime. The brain can also
serve the UI itself (`JARVIS_UI_DIST`) when you'd rather open it from another machine.

### No Docker on the Pi
`make up` uses docker compose when Docker exists, otherwise installs the brain as a native
**user** systemd service. All Pi-side services are user units (`systemctl --user`) with lingering
enabled, so they start at boot without a login and without root.
